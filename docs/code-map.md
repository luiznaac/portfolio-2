# Code map

Hand-authored module → key files → seam index, plus the app entry points — read it to go from a named seam to the file a change belongs to without a `find`/`ls` sweep. The vocabulary is the `codebase-design` one (**module**, **interface**, **seam**, **adapter**). The backend is a Gradle multi-module build (`backend/settings.gradle.kts`): `application → http-api → usecase ← persistence` and `gateway → usecase`; each Gradle module is one block below, then the backend test roots and their mirror-package convention, the frontend SPA and the repo-root infra.

- **At `configuration/JsonMapper.kt`** — the Jackson `SNAKE_CASE` shape the DTOs cross to `frontend/src/api/types.ts`; change one side and the other in the same commit.

### `backend/persistence` — Exposed adapters and migrations
**Purpose**: implements the usecase repository interfaces against MySQL via Exposed, and owns the Flyway migration tooling and the transaction template.
**Files**: per feature, a `*Repository.kt` adapter beside its `*Table.kt` — `bond/{Bond,BondOrder,BondOrderStatement,BondOrderPosition}{Repository,Table}.kt`, `checkingaccount/`, `catalog/`, `quotes/`, `index/{Index,IndexValue}*`, `institution/`, `listedasset/{Trade,Position,Attribution,Gap}*`, `order/{SuggestedOrder,TransferProposal}{Repository,Table}.kt`, `import/{Import,ImportRow}*`, `income/{CashMovementTable,IncomeRepository}.kt`, `corporateaction/{CorporateActionTable,CorporateActionRepository}.kt`, `portfolio/{Month,Snapshot,Target}{Repository,Table}.kt`, `strategy/{Strategy,Edition,EditionEntry}{Repository,Table}.kt`, `tax/{TaxCarryBucket,HarvestOptOut,HarvestPair}{Repository,Table}.kt`, `benchmark/{BenchmarkCloseRepository,BenchmarkCloseTable}.kt`; `configuration/{DatabaseConfig,TransactionService}.kt`; `health/MySqlConnectionHealthCheck.kt`; `migration/{MigrationScripts,Migrator,MysqlEnv}.kt`; `src/main/resources/db/migration/V*.sql`
**Seam(s)**:
- **Adapter seam** — each `@Component … : I*Repository` sits at the usecase interface; `TransactionService : ITransactionTemplate` at the transaction seam. The `Table` object is where the persisted shape lives; a model with a variant (e.g. `Trade.Buy`/`Trade.Sell`) translates from its single stored column in the repository (`TradeTable.toModel`, pinned by `TradeModelMappingTest`).
- **Migration seam** — a new `*Table.kt` must be added to `allTables` in `migration/MigrationScripts.kt`; schema change = edit the `Table`, generate the SQL (`:persistence:generateMigrationScript -Pname=V<n>__x`), apply it (`:persistence:migrate`, Flyway). `MigrationSchemaTest` diffs `allTables` against a migrated database and fails on drift. Baseline rules: `docs/migrations.md`.
- **Connection seam** — `configuration/DatabaseConfig.mysqlJdbcUrl` is shared by Exposed and Flyway, so the two cannot drift.

### `backend/gateway` — outbound integrations
**Purpose**: adapters for the external systems the domain calls: BACEN index rates, the BCB SGS / brapi / Yahoo benchmark chain, B3 COTAHIST, chameidor scheduling, and health.
**Files**: `index/BacenGateway.kt`; `benchmark/{BcbSgsGateway,BrapiGateway,YahooFinanceGateway}.kt`; `cotahist/{CotahistGateway,CotahistParser}.kt`; `schedule/ChameidorGateway.kt`; `health/{AppHealthGateway,HttpClientHealthCheck}.kt`; `configuration/KtorClientConfig.kt`
**Seam(s)**: each `@Service`/`@Component … : I*Gateway` sits at its usecase interface (`IIndexValueGateway`, `IBenchmarkSeriesSource`, `ICotahistSource`, `IScheduleGateway`, `HealthGateway`); the benchmark adapters are links in an ordered chain (`order`, `indexes`) that `BenchmarkSeriesStore` consumes; endpoint hosts and the chameidor token arrive through `@Value("\${gateways.*}")`. `KtorClientConfig` is the shared `HttpClient` seam. `ChameidorGatewayContractTest` pins the chameidor request body against `contracts/chameidor/tasks-one-time-request.json`.

### `backend/http-api` — Ktor routes and edge adapters
**Purpose**: the HTTP surface — controllers, broker-file parsers, report converters, domain-exception handling and the Ktor server bootstrap.
**Files**: `controller/` — `ControllerTemplate.kt`, `ControllerExtensions.kt`, and `{Bond,BondOrder,CheckingAccount,Consolidation,Catalog,Index,IndexValue,Institution,Import,Income,Trade,Position,Attribution,Month,Allocation,OrderPlan,Orders,CorporateAction,Strategy,Tax,MonthlyClose,Benchmark,Upload,Health}Controller.kt`; `import/{IImportParser,ImportParserResolver,IMovementsParser,MovementsParserResolver,B3NegotiationParser,B3PositionParser,B3IncomeParser,B3MovementsParser,XlsxCells}.kt`, `import/strategy/{IStrategyReportParser,StrategyReportParserResolver,XpTableReportParser,XpEquityCarteiraParser,XpQuantCarteiraParser,XpFiiCarteiraParser,XpGenericReportParser,XpReportText}.kt`; `configuration/{KtorConfig,DomainExceptionHandling,DomainExceptionStatusMapper,PdfConverter,XlsxConverter}.kt`
**Seam(s)**:
- **Route seam** — `controller/ControllerTemplate.kt` (`routes(): RouteDefinition`); `KtorConfig` collects every `@Component` implementing it and mounts it. Adding an endpoint is adding a controller — no manual registration. Route path-param parsing goes through `ControllerExtensions.kt` (`requiredInt`/`requiredString`/`requiredDate`/`requiredPeriod` → a `400` domain error).
- **Parser seam** — `import/IImportParser.kt` is the broker-layout interface (`shouldExecute`/`parse`); `ImportParserResolver` injects the `List<IImportParser>` and picks the first that claims the file. A new layout is a new class implementing the interface. The domain never sees bytes — `ImportController.stageFile` hashes the upload and hands the parsed rows to `ImportService.stage`.
- **Error-body seam** — `configuration/DomainExceptionHandling.kt` maps a `DomainException` to the canonical body; `contracts/error-response.json` pins it, asserted by `DomainExceptionContractTest`.
- **Content-negotiation seam** — `configuration/{XlsxConverter,PdfConverter}.kt` register the report formats on the Ktor `ContentNegotiation`.

### `backend/application` — composition root
**Purpose**: the Spring Boot entry and the runtime configuration; wires the modules together.
**Files**: `Boot.kt`, `src/main/resources/{application.yaml,application-prod.yaml,logback.xml}`, `build.gradle.kts`
**Seam(s)**: `Boot.kt`'s `@ComponentScan("dev.agner.portfolio")` is the wiring seam — every `@Component`/`@Service` is picked up, so a new class needs no registration. `application.yaml` is the config seam (env-driven `mysql.*` and `gateways.chameidor.token`; the full list is in `backend/AGENTS.md` §Configuration, including `gateways.sgs.host`/`gateways.brapi.*`/`gateways.yahoo.host` for the benchmark chain). `build.gradle.kts` adds the second start script `bin/migrate` (main class `MigratorKt`) beside `bin/application`.

### `backend/integrationTest` — full-stack tests
**Purpose**: end-to-end specs that boot the real app against a real MySQL and stubbed external gateways.
**Files**: `build.gradle.kts` (the module's dependencies plus the `dockerPreflight` task); `config/{DockerComposeExtension,IntegrationTest,HttpMockService,HttpRequestService,ClockMock,KotestConfig,ResetWiremock,StopKtorServer}.kt`; `helpers/*`; `tests/{Bond,CatalogClassification,CheckingAccount,Consolidation,MigrationSchema,MonthlyClose,TickerRefresh}Test.kt`
**Seam(s)**: `DockerComposeExtension` brings up the compose MySQL and migrates it to head before any spec runs; `HttpMockService` (WireMock) stubs the outbound gateways. `MigrationSchemaTest` is the schema guard (see `persistence`). Run via the `:integrationTest:test` Gradle task (`npm run be:integration`); `dockerPreflight` probes the daemon first and fails in seconds with an actionable message when Docker is unavailable, so the Docker-free unit lane (`unitTest`, `npm run be:unit`) is the pre-commit default and the integration lane stays in CI.

**Seam(s)**:
- **Wire contract** — `src/api/types.ts` is the hand-maintained mirror of the backend edge DTOs; any DTO change updates it in the same commit. `lib/dtoMirrorGuard.test.ts` enforces it: `lib/dtoMirror.ts` parses both sides and the guard fails on any field-name drift, with one table for a mirror whose backend type is named differently.
- **Data seam** — `src/api/client.ts` (the `fetch` wrapper, `ApiError` and the multipart `upload`) and `src/api/queries.ts` (TanStack Query hooks) are where a new API call is wired; `pages/Dashboard.tsx` is the reference read slice and `pages/ImportWizard.tsx` the reference mutation slice. `useOrderPlan` reads the computed plan (funding/outside-strategy) while `useOrders` reads the persisted lifecycle.

### Repo root — contracts, deploy, CI
**Purpose**: the cross-cutting fixtures and the packaging/deploy story that bind backend + frontend together.
**Files**: `contracts/error-response.json`, `contracts/chameidor/tasks-one-time-request.json`; `Dockerfile`, `docker-compose.yml`, `deploy/{entrypoint.sh,supervisord.conf,nginx.conf.template}`; `package.json` (script shims only), `scripts/backend-gradle.mjs`, `.github/workflows/ci.yml`, `.pre-commit-config.yaml`; `docs/{migrations.md,acceptance-runbook.md,adr/*}`
**Seam(s)**: `contracts/*` are the versioned wire fixtures the tests pin against. `scripts/backend-gradle.mjs` is the single crossing from the package scripts and the pre-commit hooks into Gradle — it resolves `gradlew.bat`/`./gradlew` for the host, so a new `be:*`/`db:*` script goes through it rather than re-deriving the wrapper invocation. The one image runs the JVM app (`API_PORT`/8080) and nginx (`WEB_PORT`/8081, reverse-proxying `/api`) under supervisord; `deploy/entrypoint.sh` runs `bin/migrate` then the app. `package.json` is a script-only shim (`npm run be:unit`, `npm run check`, `npm run db:migrate`, `npm run up`, …), not a real package.

## Backend tests

Backend tests live in each module's `src/test/kotlin`, in the **mirrored package**: the same `dev.agner.portfolio.<module>.<feature>` path as the production code, so a change at the usecase `quotes` seam has its tests in `usecase/quotes/`. Most are `<ClassName>Test.kt` beside the class they cover; the rest are scenario tests named for the behaviour they pin. `usecase` also carries `src/testFixtures/kotlin`, holding helpers shared across its tests and by the module tests that depend on them.

| Module | Test source root(s) |
| --- | --- |
| `usecase` | `src/test/kotlin`, `src/testFixtures/kotlin` |
| `persistence` | `src/test/kotlin` |
| `gateway` | `src/test/kotlin` |
| `http-api` | `src/test/kotlin` (package `httpapi`, not `http-api`) |
| `integrationTest` | `src/test/kotlin` — test-only module with no `src/main`, so its packages are not mirrored from production |
| `application` | none |

**Search the mirrored package for an existing test before creating one, and extend it rather than overwrite it** — an earlier session wrote a fresh `QuoteServiceTest` over the `fetchAllBy`/`refreshEod` cases already there; only a later `git status` caught it.

## Entry points

- `backend/application/src/main/kotlin/dev/agner/portfolio/application/Boot.kt` — the app: Spring Boot `main()` that component-scans `dev.agner.portfolio` and starts the server.
- `backend/http-api/src/main/kotlin/dev/agner/portfolio/httpapi/configuration/KtorConfig.kt` — the HTTP route table: mounts every `ControllerTemplate`, installs content negotiation, CORS and the domain-exception handler, and blocks the main thread (`ktor.wait: true`).
- `backend/persistence/src/main/kotlin/dev/agner/portfolio/persistence/migration/Migrator.kt` — `main()`, the Flyway migrator packaged as `bin/migrate`; `deploy/entrypoint.sh` runs it before the app.
- `backend/persistence/src/main/kotlin/dev/agner/portfolio/persistence/migration/MigrationScripts.kt` — `main()`, the Exposed migration-script generator.
- `frontend/src/main.tsx` — the SPA: mounts React with the TanStack Query client and the router.
- `deploy/entrypoint.sh` + `deploy/supervisord.conf` — the container entry: migrate, then run the JVM app and nginx.
