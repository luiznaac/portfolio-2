# Research: B3 Área do Investidor exports — movements and custody position

- **Ticket:** [luiznaac/portfolio-2#94](https://github.com/luiznaac/portfolio-2/issues/94) — "Research: parse B3 Área do Investidor exports"
- **Date:** 2026-09-15
- **Branch:** `research/b3-extract` (worktree `../.worktrees/portfolio-2-research-b3-extract`)
- **Question (verbatim from the issue):**

> Which exports does B3's Área do Investidor provide (negociações/extrato, posição em custódia), in what
> formats (CSV/XLSX/PDF), with which fields — and can they (a) feed the movements ledger and (b) seed initial
> positions?
>
> Cover: operation types, quantities, prices, costs, acoes vs FIIs, proventos/corporate actions if present,
> file granularity (per period?), and stable keys for dedup. Input: sample in `references/`.
>
> Deliverable: findings (per the `research` skill) + a mapping sketch for the import design.

## Answer (short)

- **Exports exist for both sides of the question, in Excel and PDF.** Área do Investidor
  (`investidor.b3.com.br`) exposes extratos of *negociação* (buys/sells), *movimentações*
  (aplicações, eventos, vencimentos), *posição em custódia* and *proventos*, and its reports can be
  exported "em PDF ou como arquivo Excel" (B3-owned Bora Investir). The sample under `references/` is
  an XLSX of the **Negociação** export: one sheet `Negociação`, 9 columns, 82 execution rows
  (06/08, 10/08, 11/08/2026), XP as the only broker.
- **It can feed the movements ledger for listed-asset buys/sells** (date, side, market, ticker,
  quantity, unit price, gross value, broker) but carries **no costs/fees** (`Valor` is exactly
  `Quantidade × Preço` in all 82 rows), **no proventos/corporate actions**, no trade time, no account
  number and **no row identifier**.
- **Initial positions can be seeded in quantity, not in cost.** B3's own *Posição* data model (and the
  B3 For Developers swagger below) carries quantity, closing price, market value, ISIN, specification
  and broker per ticker — but **no acquisition cost / average price for equities**. Average price must
  come from the manual ledger (`MOVIMENTACOES RENDA VARIAVEL.xlsx`, see gap below), Kinvo or manual entry.
- **Dedup key:** the export has no stable id, so the design must key on the natural tuple
  `(trade_date, side, market, ticker, quantity, unit_price, broker)` plus an **occurrence ordinal**
  within identical tuples, scoped to the import batch, and reconcile against the position snapshot.
  Re-exports of overlapping periods re-insert the same rows; dedup **must not** be file-based.
- **The same data via API is B2B-only.** B3 For Developers publishes official APIs (Guia, Posição,
  Movimentação, Negociação de ativos, Eventos Provisionados…), but states "Nossas APIs são destinadas
  ao consumo de clientes B2B. Não oferecemos acesso direto às APIs para pessoas físicas." — so the file
  export is the only route for this app; the API docs remain the best public description of the data model.

## 1. What the portal offers

### 1.1 Evidence from B3-owned pages

- The B3 "Canal com Investidores → Área do Investidor" page lists what the platform provides
  (fetched 2026-09-15): "consultar os extratos de posições e movimentações de todas as suas aplicações
  financeiras", with "Extratos (Listado, Balcão e Tesouro Direto)", "Histórico de negociações",
  "Movimentações (aplicações, eventos e vencimentos)", "Rendimentos (por exemplo: dividendos)",
  "Empréstimo de títulos", "Informe de rendimento e reembolso de empréstimos de títulos"
  (<https://www.b3.com.br/pt_br/produtos-e-servicos/central-depositaria/canal-com-investidores/area-do-investidor/>).
- B3 Educação's Área do Investidor page (fetched 2026-09-15) states the platform offers "a consulta da
  **posição em custódia** dos ativos, **emissão de extratos mensais** e informes de rendimento para
  facilitar a declaração do Imposto de Renda, além da **verificação dos proventos recebidos**", and
  that it is read-only ("sem possibilidade de realizar operações de compra ou venda de ativos")
  (<https://edu.b3.com.br/w/area-investidor>).
- B3's Bora Investir article (B3-owned site) says: "A plataforma também gera relatórios com diversos
  filtros [...] que podem ser **exportados em PDF ou como arquivo Excel**"; and "Em Relatórios, o
  investidor tem acesso a um documento que consolida as informações dos outros menus, com a
  possibilidade de escolher entre dados **mês a mês ou ano a ano**"; the asset list includes "Ações,
  Fundos imobiliários, ETFs, BDRs, Tesouro Direto, Ativos de renda fixa, Derivativos"; and "o investidor
  ainda pode acessar uma aba que unifica todas as informações referentes aos **proventos**, como
  dividendos, juros sobre capital próprio e garantias"
  (<https://borainvestir.b3.com.br/objetivos-financeiros/organizar-as-contas/o-que-e-a-area-do-investidor-da-b3/>).
- So, **formats**: XLSX evidenced by the sample and by B3's own text ("arquivo Excel"); PDF documented
  for reports. **CSV: no B3-owned or sample evidence** — assume not available.
- **Granularity**: the report filters allow choosing the period (the IR report is "mês a mês ou ano a
  ano"); the API equivalent takes a `referenceStartDate`/`referenceEndDate` range. Expect **user-chosen,
  potentially overlapping date ranges**, not one canonical file per month.

### 1.2 The sample file (`references/movimentacoes_B3.xlsx`)

Parsed directly from the OOXML zip (Python unavailable; Node/zlib + PowerShell used).

- **Workbook:** a single visible sheet named `Negociação` (`xl/workbook.xml`); no defined names, no
  other sheets. Rows 2–83 = 82 data rows under one header row (`sheetData` cells `A1:I83`).
- **Columns** (header row 1, shared strings):

| Col | Header | Stored as | Sample value (row 2) | Notes for the domain |
| --- | --- | --- | --- | --- |
| A | `Data do Negócio` | text (style `dd/MM/yyyy`) | `11/08/2026` | trade date; **dd/MM/yyyy string**, not an Excel serial |
| B | `Tipo de Movimentação` | text | `Compra` | only `Compra` (59) and `Venda` (23) in the sample |
| C | `Mercado` | text | `Mercado Fracionário` | only `Mercado à Vista` (29) and `Mercado Fracionário` (53) |
| D | `Prazo/Vencimento` | text | `-` | `-` in 76 rows; a date in 6 (see anomaly below); maps to the API's `expirationDate` |
| E | `Instituição` | text | `XP INVESTIMENTOS CCTVM S/A.` | broker; same value in all 82 rows; **no account number/CPF** |
| F | `Código de Negociação` | text | `ALOS3F` | ticker, uppercase |
| G | `Quantidade` | number | `7.0` | positive for both Compra and Venda |
| H | `Preço` | number (2 dp, currency style) | `26.09` | unit price |
| I | `Valor` | number (2 dp, currency style) | `182.63` | **exactly `Quantidade × Preço` in all 82 rows** |

- **Row semantics:** one row per **execution**, not aggregated per asset/day. Same ticker/day appears
  multiple times at different prices (e.g. `EZTC3F` on 06/08: 65 @ 11.03, 20 @ 11.04, 6 @ 11.05;
  `B3SA3F` on 11/08: 6 @ 14.26, 66 @ 14.54), and the same asset appears in both venues the same day
  (`B3SA3` 200 @ 14.27 "Mercado à Vista" + `B3SA3F` 6 @ 14.26 and 66 @ 14.54 "Mercado Fracionário").
  The ledger must preserve executions (average price and day-trade/swing tax depend on them).
- **Ordering:** grouped by date **descending** (11/08 → 10/08 → 06/08), within a day by file/execution
  order, not sorted by ticker. No trading day is empty in between (07–09/08 omitted; 07/08/2026 was a
  Friday, so this is a *custom range* export, not a contiguous calendar dump).
- **Coverage:** 63 distinct tickers — 36 with the fractional suffix `F`, 22 with suffix `11`
  (FIIs/units/ETFs, e.g. `BRCO11`, `MXRF11`, `ALUP11`, `KNCR11`), 1 BDR (`ROXO34`, confirmed as
  "NU HOLDINGS DRN" via B3's own quote endpoint `https://cotacao.b3.com.br/mds/api/v1/instrumentQuotation/ROXO34`),
  and 4 common shares (`B3SA3`, `CPLE3`, `EGIE3`, `ITSA4`), most of which also appear in the fractional
  venue. **There is no asset-class column** — FII vs share vs unit vs BDR must be resolved by the app
  (ticker suffix or, better, an asset registry).
- **No fees anywhere:** no corretagem, emolumentos, ISS, liquidação or IRRF columns; `Valor` is gross
  (`Quantidade × Preço`). The net cash effect of a buy is `-Valor - fees`, and the fees are simply not
  in this export.
- **`Prazo/Vencimento` anomaly:** 6 rows carry a date **equal to the trade date** instead of `-`
  (10/08: `BPAC11F` 11 @ 53.70, `ORVR3F` 8 @ 67.29, `ORVR3F` 6 @ 67.32, `PCIP11` 12 @ 74.88;
  11/08: `ENGI11F` 4 @ 45.98, `VALE3F` 2 @ 74.38). No B3 doc read explains it; the Negociação API field
  is `expirationDate`. Treat it as pass-through metadata, not a ledger field.
- **Structural caveat:** the XLSX has Mac-Excel namespaces, an `xl/persons/person.xml`, an empty
  `drawing1.xml` and no `docProps/` — signs of a round-trip through Excel for Mac after download. Cell
  *values* are consistent and complete; styling/typing of a raw B3 download may differ.
- No other B3-derived sample exists in the main checkout: `MOVIMENTACOES RENDA VARIAVEL.xlsx` (the
  Aplicações/Resgates ledger referenced by the map) is **not present** under `references/` (only
  `movimentacoes_B3.xlsx`, the Kinvo extrato, the XP report PDFs and the UI prototype). Its columns
  could not be inspected.

## 2. What the official APIs say (same data, B2B-only)

B3 For Developers (<https://developers.b3.com.br/apis/api-area-do-investidor>) publishes the Área do
Investidor APIs, with the disclaimer on the home page: **"Nossas APIs são destinadas ao consumo de
clientes B2B. Não oferecemos acesso direto às APIs para pessoas físicas."** (fetched 2026-09-15). The
overview page also says the APIs exist "mediante autorização do investidor" and a contract
(<https://www.b3.com.br/pt_br/produtos-e-servicos/central-depositaria/canal-com-investidores/integracoes-da-area-do-investidor-apis/>).
The public swagger definitions were fetched from the portal's own ajax endpoint
(`/index.php?option=com_apiportal&task=ajaxrequest.swaggerLoad&apiId=…`, 2026-09-15); quotes below are
from those definitions. They are the most exact public description of what B3 holds, and the web
exports are the same data sets:

- **Negociação de Ativos** (`apiId 7eeab8be-e806-4b33-9882-13eb1a291765`) — "Dados até D-1 de todas as
  compras e vendas (ativos listados) do investidor." Model `AssetTrading`: `tickerSymbol`, `side`
  ("Tipo de movimento. - Compra - Venda"), `marketName` ("Mercado a vista / Derivativos"),
  `expirationDate`, `participantName` + `participantDocumentNumber` (corretora), `assetTradingObjectCode`,
  `optionExerciseValue`, `tradeQuantity`, `priceValue`, `grossAmount`, `originalTradePriceValue`,
  `originalTotalAdjustmentValue`, `tradeDateTime` (**date-time**), `participantCode`, `accountNumber`.
  Period wrapper `PeriodList`: `referenceDate`, `buyTotal`, `sellTotal`, `assetTradings[]`.
- **Movimentação** (`apiId d713c392-a0cc-4003-96e8-66b58988f411`) — "Dados até D-1 das transações
  ocorridas nas contas do investidor em um determinado período." Overview: "Está previsto os seguintes
  tipos de movimentação: **Movimentação de custódia** (transferência de ativos, liquidação de compra e
  venda), **Eventos Corporativos** (pagamento de dividendo, grupamento, desdobramento), **Empréstimos
  de ativos** (abertura de contrato, liquidação de contrato e reembolso de evento)." Endpoints:
  securities-lending, equities, fixed-income, treasury-bonds, derivatives. `EquitiesMovement` fields:
  `referenceDate`, `productCategoryName`, `productTypeName`, `movementType`, `operationType`
  ("Débito Crédito"), `tickerSymbol`, `corporationName`, `participantName`/`DocumentNumber`,
  `equitiesQuantity`, `unitPrice`, `operationValue`, `transferOwnershipDescription`, `isinCode`,
  `baseIsinCode`, `movementTypeDetailCode`, `processNumber`.
- **Posição** (`apiId 691d82de-4e9c-4be8-be31-b66fa9bbaa62`) — "Dados até D-1 do saldo de investimentos
  nas contas do investidor", including gravames. `EquitiesPosition` fields: `documentNumber`,
  `referenceDate`, `productCategoryName`, `productTypeName`, `markingIndicator`, `tickerSymbol`,
  `corporationName`, **`specificationCode`** (ON, PN…), `participantName`/`DocumentNumber`,
  `equitiesQuantity`, **`closingPrice`**, **`updateValue`**, `isin`, `distributionIdentification`,
  `bookkeeperName`, `availableQuantity`, `unavailableQuantity`, `administratorName`, `participantCode`,
  `accountNumber`, `reasons[]`. **There is no `applicationValue`/average cost for equities** (the fixed
  income model has `applicationValue`; the equities one does not).
- **Eventos Provisionados** (`apiId d06a2a08-50b0-41e9-a412-3900bb2863ec`) — "provisionamento de
  recebimento de pagamentos de proventos": `corporateActionTypeDescription` domain includes
  `DIVIDENDO`, `RESTITUIÇÃO DE CAPITAL`, `BONIFICAÇÃO EM DINHEIRO`, `JUROS SOBRE CAPITAL PRÓPRIO`,
  `RENDIMENTO`, `JUROS`, `AMORTIZAÇÃO`, `PRÊMIO`, `ATUALIZAÇÃO MONETÁRIA`, `BONIFICAÇÃO EM ATIVOS`;
  fields `eventValue` (money **or factor**), `eventQuantity`, `grossAmount`, `netValue`,
  `incomeTaxPercent`/`incomeTaxAmount`, `paymentDate`, `specialExDate`, `approvalDate`, `updateDate`,
  `tickerSymbol`, `isin`, `specificationCode`, plus custodian/corporation names.
- **API Guia** (`apiId 0bdaa807-c025-47e0-aeaa-a41be6bb2a13`) — the products enum that enumerates the
  data sets: `ProvisionedEvents`, `Collaterals`, `AssetsTrading`, `PublicOffers`,
  `DerivativesMovement`, `SecuritiesLendingMovement`, `FixedIncomeMovement`, `EquitiesMovement`,
  `TreasuryBondsMovement`…
- **Manual Técnico — APIs Área do Investidor da B3** (PDF, version 12/12/2024, linked from the B3 page
  above): "Negociação de Ativos: Dados até D-1 de todas as compras e vendas do investidor";
  "Posição: Dados até D-1 do saldo de investimentos na conta do investidor"; "Movimentação: […]
  Empréstimo de Ativos, Tesouro Direto, Renda Fixa, Derivativos, Renda Variável (Equities)"; for
  Renda Fixa Balcão only "quantidade, ISIN, data de aquisição e vencimento são informados". The manual
  also shows the licensing/tariff model (B2B contract, fixed connectivity fee) — out of reach for an
  individual, and irrelevant to a personal app except as documentation.
- **Transferable practice from the API docs:** consumers should "consultar cada CPF uma vez por dia" and
  "buscar os dados somente do período que ainda não tenha sido consultado anteriormente" — i.e. the data
  set is append-only and **incremental ingestion by never-queried periods is B3's own guidance**.

## 3. Can they feed the ledger and seed positions?

### 3.1 Movements ledger — yes for listed buys/sells, with gaps

| Ledger need | Negociação export | Where it comes from |
| --- | --- | --- |
| Trade date | yes `Data do Negócio` (dd/MM/yyyy string) | — |
| Direction | yes `Tipo de Movimentação` (`Compra`/`Venda`); `Valor` is always positive — derive sign from the type | — |
| Asset | yes `Código de Negociação`; **no asset class** | infer class (or asset registry) |
| Quantity / unit price / gross value | yes `Quantidade`, `Preço`, `Valor` (gross = qty × price) | — |
| Venue | yes `Mercado` (`à Vista`/`Fracionário`) | — |
| Broker | yes `Instituição` (name only; no CNPJ/account) | — |
| **Fees (corretagem, emolumentos, ISS, liquidação)** | no | manual entry / broker note |
| **Proventos (dividendos, JCP, rendimentos)** | no | B3 *Proventos* tab / *Movimentações* export / *Eventos Provisionados* |
| **Corporate actions (split, bonificação, grupamento, subscrição)** | no (not in the sample; the Movimentação data set has them) | B3 *Movimentações* export or manual |
| Transfers in/out between brokers | no | B3 *Movimentações* export or manual (affects quantity, no cash) |
| Time of trade / account / unique id | no in the export (the API has `tradeDateTime`, `accountNumber`) | — |

So the B3 extract replaces the nota de corretagem for **what was traded**, but not for **what it cost**
— the ledger needs a fees source (manual, as the map already assumes manual entries exist).

### 3.2 Initial positions — quantity yes, cost no

- The *Posição* data set (web export and API) gives, per ticker/participant: quantity, closing price
  and updated market value, plus ISIN, specification, gravames, availability. That seeds a position
  snapshot for listed assets.
- **It does not carry acquisition cost / average price for equities** (API model, §2). The portal UI
  reportedly shows "valor aplicado" (Bora Investir), but that was not verifiable for the *export*, and
  the API's equities position model has no such field. Seed cost must come from the manual ledger
  (`MOVIMENTACOES RENDA VARIAVEL.xlsx` — the map's Aplicações/Resgates file, not present in `references/`),
  Kinvo (per ticket #96, only a year-end, at-cost IR report) or manual entry.
- Alternative: derive positions by replaying the movements ledger from the beginning of history — but
  that only works with full backfill, which is exactly the open "backfill depth" question in the map
  (#88) and the subject of ticket #102.

## 4. Mapping sketch for the import design

Two import artifacts: **(A) executions → movements ledger** and **(B) position snapshot → position
seed/reconciliation**. Keep an **import batch** row per file for audit/idempotency.

### 4.1 Sample columns → ledger fields (Negociação)

| Export column | Ledger field | Rule |
| --- | --- | --- |
| `Data do Negócio` | `tradeDate : LocalDate` | parse `dd/MM/yyyy`; reject unparseable rows |
| `Tipo de Movimentação` | `direction : BUY \| SELL` | `Compra` → BUY, `Venda` → SELL; unknown → quarantine |
| `Mercado` | `venue : CASH \| FRACTIONAL` | `Mercado à Vista` → CASH, `Mercado Fracionário` → FRACTIONAL; keep raw string for audit |
| `Prazo/Vencimento` | `rawMetadata` (not modelled) | `-` or a date; unresolved semantics (§1.2) |
| `Instituição` | `brokerName` | normalize; may become an institution entity |
| `Código de Negociação` | `ticker` | uppercase; asset class derived separately (registry, suffix as fallback) |
| `Quantidade` | `quantity : Decimal` | keep positive; sign derived from `direction` |
| `Preço` | `unitPrice : Decimal` | 2 dp |
| `Valor` | `grossAmount : Decimal` | **assert `Valor == Quantidade × Preço`**; mismatch → quarantine |
| — | `source : B3_NEGOCIACAO` | together with `importBatchId`, `importedAt` |
| — | `dedupKey` | see 4.3 |

Asset class has no column: map by ticker via a registry keyed on the B3 product taxonomy
(ACOES / FUNDOS IMOBILIARIOS / BDRs / ETFs / units) rather than by suffix alone — `ALUP11` (unit) and
`MXRF11` (FII) share the `11` suffix.

### 4.2 Position fields to seed

| Source (Posição export/API) | App field | Note |
| --- | --- | --- |
| `tickerSymbol` | `ticker` | |
| `equitiesQuantity` | `quantity` | seed |
| `closingPrice` | `referencePrice` | snapshot price, not cost |
| `updateValue` | `marketValue` | |
| `referenceDate` | `asOfDate` | D-1 of the request (API); check web export date basis |
| `participantName` / `participantCode` / `accountNumber` | `broker` / `account` | export may not carry all of these |
| `isin`, `specificationCode`, `distributionIdentification` | asset identity | useful for the asset registry |
| `markingIndicator`, `unavailableQuantity`, `reasons[]` | gravames | keep for reconciliation; not tradable quantity |
| — | `averagePrice` / `costBasis` | **not in the source** — manual/Kinvo/ledger replay |

### 4.3 Dedup key

No column in the export identifies a movement: no trade id, no nota number, no timestamp, no account
— and even the API's own `AssetTrading` only becomes near-unique with `tradeDateTime` + `accountNumber`,
which the export lacks. Identical execution tuples are theoretically possible (a broker splitting an
order into equal fills at the same price), so a pure natural key can silently **merge real duplicates**.

Proposal:

1. **Row-level key**: `sha256(tradeDate | direction | venue | ticker | quantity | unitPrice | brokerName
   | occurrenceOrdinal)`, where `occurrenceOrdinal` disambiguates byte-identical rows in the order B3
   delivered them within the batch. This is stable across re-exports of overlapping periods as long as
   B3 enumerates identical executions consistently — which is **not guaranteed**, hence point 3.
2. **Batch-level idempotency**: `sourceFileShellHash` (sha256 of the file bytes) + declared period;
   importing the exact same file twice is a no-op. But dedup must **not** rely on the file: overlapping
   periods are expected (`referenceStartDate`/`referenceEndDate` style filters), and rows from an
   overlapping re-export must dedup against the ledger, not re-insert.
3. **Reconciliation invariant**: after import, per `(ticker, broker)` the ledger's net quantity from
   all history must equal the *Posição* snapshot quantity. Mismatches are surfaced for review; tuple
   collisions (ordinal ambiguity) land in a quarantine list rather than silently merging or duplicating.
4. **Period-incremental ingestion**: follow B3's own guidance for the API — request only periods never
   imported before; treat days already imported as immutable (D-1 data can be re-delivered only by
   explicit re-export).

### 4.4 Explicit gaps needing manual entry or another source

- **Fees** (corretagem/emolumentos/ISS/liquidação) — not in any B3 export read; needed for real cost
  basis and DARF. Manual ledger.
- **Average price of the initial seed** — not in the Posição data; manual/Kinvo, or ledger replay.
- **Proventos received/to receive and their tax** — *Proventos* tab / *Eventos Provisionados* data set;
  needs its own export check in-account (no sample).
- **Corporate actions** (split, bonificação, grupamento, subscrição, restitution) — *Movimentações*
  data set has them; the Negociação export does not. Manually applies to quantity and average price.
- **Transfers between brokers/accounts**, subscriptions and other cash-less custody events — Movimentações
  export or manual.
- **Renda fixa, Tesouro Direto, caixa** — out of the Negociação/Posição equities scope; manual per the map.
- **`MOVIMENTACOES RENDA VARIAVEL.xlsx`** (the existing manual Aplicações/Resgates ledger) — absent from
  this checkout's `references/`; its actual columns and contents remain to be seen when #100 is worked.

## Open uncertainties

- **No sample of the *Posição* export** (XLSX/PDF). Exact web columns are unverified; the mapping above
  uses the API model, which is the superset. In-account check needed: does the export carry custo/preço
  médio or "valor aplicado" (the Bora Investir article says the UI shows "valor aplicado")?
- **No sample of *Movimentações* or *Proventos*** exports either; whether proventos are exportable as a
  table (not just shown/PDF) is unverified.
- Whether the web Negociação export can include trade time and account (API has both) — if yes, dedup
  becomes exact rather than ordinal-based.
- Export granularity limits (max date range, file naming, whether B3 truncates long ranges) unknown; the
  sample is a custom 06–11/08/2026 window and the file was re-saved in Excel, so the raw download
  structure could differ.
- The `Prazo/Vencimento` values on 6 rows are unexplained.
- Fees: confirm whether the portal's Negociação screen (or an adjacent "Extrato" report) shows costs;
  current evidence says the export does not.
- API access for individuals is explicitly denied today; if B3 ever opens it, the import design could
  switch from file parsing to HTTP with minimal mapping changes (same data model).
